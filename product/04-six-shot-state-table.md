> **Rule — How to use this table**  
> One row per shot, filled left to right. Row 1 is the anchor shot: it establishes everything and inherits nothing. Every row after it starts by copying the row above into “Inherits from”, and only then writes what is different.

The table is split into three panels because a table wide enough to hold every field cannot be printed or filled in by hand. Panel A is what must not move. Panel B is the handoff. Panel C is the shot itself. Use a shot card (last page) when you want one shot on its own in front of you.

| Marker | Meaning |
|---|---|
| F | Fixed — Locked for the whole sequence. Copy it into every shot word for word. |
| C | Changed intentionally — This shot deliberately differs from the one before it. The change has a code. |
| U | Unresolved — You have not decided yet. It is allowed to stay open, but not silently. |
| N/A | Not applicable — The field does not apply to this shot. Say why in three words. |

> **Tip — N/A is a real answer**  
> In an insert with no face, the anchors are not checkable — write what replaces them (“hands only: ring on the left hand, pencil in the same hand”). A blank cell reads as “I forgot”; N/A reads as “I decided”.

> **Watch out — Two things that break the ledger**  
> Rewriting the inherited line in your own words, which hides the moment the state changed — and writing “none” in the changes column for a shot where something did change. Both are easy to spot: if a later shot cannot be explained by the chain, the chain is wrong.

> **Tip — Write the watch-outs last, and write them as instructions**  
> “Mug must not stand up again” beats “cup is tipped”. An instruction tells your future self what to prevent; a description only tells them what you saw once.

# Hero prop register

Only the props you would notice if they changed. Four or five is plenty. Give each a code and, where it changes, a state code: P-01a, P-01b. A prop with a state code is a prop your continuity depends on.

## Drift log

After each generation: two lines about what came out and what you did about it. This is the only record that will teach you your own failure patterns.

|---|---|---|---|---|

|  |  |  |  |  |

## What a useful entry looks like

```
SHOT 5 · try 2
  came out   cardigan still buttoned, mug upright, door frame-left
  verdict    drift in the anchors
  action     re-generated with the anchor line first, action last

SHOT 2 · try 1
  came out   perfect except a wall clock above the door
  verdict    drift outside the frame's business
  action     kept; cropped in the edit, logged so it is not repeated
```

Two entries are enough to see the pattern. The first is a state that slipped; the second is a decision you made on purpose and wrote down, which is why it is not drift.
