# The Continuity Bible

A six-shot handoff system for independent AI filmmakers: a character sheet, a location sheet, a six-shot
state table, a preflight checklist, a field dictionary, and one complete worked example — so that six
separately generated shots can be made to feel like one scene.

**Version 1.0 · November 2026 · test price US$29 (unvalidated).**

> Continuity is a production judgment supported by a written record. This product does not eliminate
> continuity drift, and nothing in it claims to.

---

## Start here

- **Buying or reading it:** open `product/README-first.md`, then `product/00-start-here.md`.
- **Printing it:** `product/The-Continuity-Bible-v1.0.pdf` (A4, 43 pages).
- **Editing it:** the seven Markdown files in `product/` are the source. Lines of underscores are writing
  space.
- **Filling it in on a laptop:** open `tools/continuity-form.html` in any browser. One file, offline, no
  account, exports plain text.

## What is in the product

| Layer | Where it lives | Question it answers |
| --- | --- | --- |
| **Identity** | character sheet, location sheet | What must never change? |
| **Variant** | variant and light-state registers | What changed on purpose, and why? |
| **Shot state** | six-shot table | What exactly is true in this shot? |
| **Handoff** | inherits / changes / hands off | What does the next shot receive? |

Every field in the dictionary answers four questions: what it records, what stays fixed, what may change,
and how an intentional change is recorded. Status markers are **F** fixed, **C** changed intentionally,
**U** unresolved, **N/A** not applicable — always as letters with words, never colour alone.

## Building it yourself

```bash
python3 -m pip install --break-system-packages reportlab pypdf
python3 src/check_example.py        # 86 mechanical checks on the worked example
python3 src/build_md.py             # writes product/*.md and product/spreadsheets/*.csv
python3 src/build_pdf.py            # writes product/The-Continuity-Bible-v1.0.pdf
python3 src/build_site.py           # writes site/index.html and site/files/*
```

The PDF needs `assets/fonts/*.ttf` in place; nothing else is downloaded at build time.

The form test needs Node and jsdom:

```bash
npm install --no-save jsdom
node tools/tests/test-form.mjs      # 35 functional checks
node tools/tests/test-site.mjs      # 44 functional checks on site/index.html
```

## Quality checks actually performed

- `src/check_example.py` — **86 checks, all passing**: six shots in order, every code declared and used,
  variant and light contiguity, status agreeing with change, frame-side rules (door and lamp frame-right,
  mug frame-left, pencil in the left hand), the 1↔6 bookend, the mug-state run, no clock anywhere, every
  schema field present, and a scan for banned promises ("guaranteed", "never drifts").
- `tools/tests/test-form.mjs` — **35 checks, all passing**: the form builds all fields with labels, survives
  a realistic fill-in, and the exported text contains what was typed, with no `undefined` or `null`.
- PDF: 43 pages, fonts embedded, text extractable, every page rendered and inspected as images for
  overflow, orphans and empty pages.
Full record, including what these checks cannot prove: `validation/QA-RECORD.md`.
- `tools/tests/test-site.mjs` — **44 checks, all passing**: no external requests, every download target
  exists, the preflight counter/persistence/reset work, the published handoff lines match the book, and no
  banned claim appears on the page.
- **Not done:** no filmmaker has read or used any of this. The two validation activities in `validation/`
  are written and ready to send, and neither has been run.
